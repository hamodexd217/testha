BigMoeOnEdge+ 0.6.0 — upstream/Flint source audit
Date: 2026-10-24

WHAT I VERIFIED
- App source is native Android/Kotlin/JNI with custom BigMoeOnEdge core 0.28.1, based on 0.28.0.
- The app's CMakeLists identifies its vendored llama.cpp as snapshot 965f897 (2026-09-26); its source lacks LLM_ARCH_FLINT and src/models/flint.cpp.
- The app's expert-streaming registry has no "flint" recipe.
- The provided BigMoeOnEdge 0.35.0 ZIP has an empty third_party/llama.cpp directory because this dependency is a Git submodule.
- GitHub metadata for Helldez/BigMoeOnEdge tag v0.35.0 pins that submodule to ad98071a583d66c922ba36264433e0435f0e0b42. At that commit, src/models/flint.cpp and LLM_ARCH_FLINT are present.
- Upstream llama.cpp PR #30928 adding Flint support was merged 2026-10-21: https://github.com/ggml-org/llama.cpp/pull/30928

WHY I DID NOT BLINDLY MERGE
The matching llama.cpp source is absent from the supplied ZIP, and the upstream core 0.35.0 has a newer planner/runtime API than the app's JNI/Kotlin integration. Replacing either native tree wholesale could break local expert-ready-hook changes, Qwen4Exp, MTP, multimodal requests, or app API contracts. A complete Flint port also needs the model graph, vocabulary/tokenizer/template changes, tensor mapping, numerical scaling behavior, and an expert-streamer recipe; adding an architecture string alone is not support.

- README.md: clearly states Flint is not supported in this source revision.
